# Independent Android client

This is an AGPL-3.0 fork of `deranjer/bookorbit-android`, not the official
BookOrbit application. Keep upstream attribution and compatible engine licenses.
Do not import production databases, secrets or books into development fixtures.

## Актуальный план после тестирования пользователем

Обновлено 2026-11-26. Этот раздел задаёт текущие приоритеты; разделы ниже —
история уже сделанных инкрементов, а не заявление о готовности всего приложения.

  ветка `feat/independent-android-client`: 551 JVM-тест на вариант, 27 JS-проверок,
  14 Python-проверок; оба lint без ошибок. Это не полная проверка

  Срезы до `43013c0` отправлены в origin; следующие изменения сохраняются локально

  сохранены отдельно в `.local/apks/`; новый публичный релиз не создавался.

  scoped Range-source, clip queue, обёртка ExoPlayer/MediaSession и арбитр
  непересекающихся READ/LISTEN-интервалов. Собраны оба варианта и пройдены
  511 JVM-тестов на вариант; подробные границы эмуляторной проверки —

- Пользователь тестирует APK. Производственный сервер и его данные агент не меняет.
- **Ошибка сценария выбора:** у пользователя одна аудиокнига состоит из 75
  аудиофайлов. 75 чекбоксов неприемлемы: выбирать нужно издание, а не каждый трек.
- **Замечание к дизайну:** интерфейс выглядит устаревшим и слишком шаблонным.
  Нужен современный целостный дизайн, а не только перекрашивание стандартных кнопок.
- **Баг читалки:** в тёмной теме видны границы/прямоугольники страниц, фон страницы
  отличается от окружающего фона. Пока это подтверждённое пользователем проявление,
  но причина и исправление ещё не проверены.
- **Баг навигации:** повторное нажатие уже выбранной вкладки не возвращает на её
  начальный экран, если внутри открыт экран книги или другой вложенный экран.
- **Ошибка приоритизации разработки:** read-along и AI были обещаны, но пока не
  реализованы. Не заменять их бесконечными второстепенными доработками офлайна.

### Порядок выполнения

#### Офлайн read-along — рабочий срез 2026-11-26

- Приоритет восстановлен: реализуется именно локальный native EPUB/SMIL source,
  без новых работ над декодером, ИИ, статистикой и без изменений production-сервера.
- Убрано исключение скачанных EPUB из native-пути. Общий интерфейс источника
  сохраняет существующий HTTP API, очередь, ExoPlayer/MediaSession, арбитраж и
  fingerprint-scoped checkpoints. Если есть локальный файл, выбирается только он;
  ошибка локального источника не приводит к HTTP или скрытому WebView-аудио.
- LocalRef (обычный файл/SAF) копируется в приватный ограниченный snapshot с
  повторной проверкой SHA-256. OPF/spine/SMIL читаются локально; аудио извлекается
  лениво при открытии DataSource в seekable временный файл, а не при просмотре
  библиотеки/синхронизации. Временный аудиофайл удаляется при закрытии DataSource;
  snapshot освобождается после последнего читателя. Следующий процесс убирает
  осиротевшие файлы только в выделенном каталоге native narration.
- Границы первого среза: snapshot до 2 GiB, аудиоресурс до 1 GiB, XML до 4 MiB
  на документ/32 MiB суммарно, до 100000 записей/клипов. DTD/внешние сущности,
  неоднозначные ZIP-имена, внешние/выходящие из архива ссылки отклоняются.
  Крупные аудиоресурсы пока извлекаются заново для каждого открытия клипа;
  производительность на реальных книгах ещё не принята.
- Добавляются JVM-проверки часов/URI/spine/точного resume/XXE/дубликатов/лимитов
  и instrumentation настоящего локального PCM playback/seek/перехода между SMIL
  clips при недоступном URL сервера, ревизии/владельца и очистки временных файлов.
  Итоговые результаты будут записаны после запуска; сам факт реализации не
  означает приёмку фона/подсветки/SAF/завершения процесса на устройстве.
- Первый Android-запуск выявил неподдерживаемые Harmony-парсером JAXP feature flags.
  Исправлено: обязательный лексический запрет DTD (включая UTF-16/32) и throwing
  EntityResolver сохраняются независимо от поддержки дополнительных флагов.
  После исправления 2 instrumentation-теста прошли дважды:
  `.local/instrumentation/20261126T101547391229Z/`. Это настоящий локальный
  ExoPlayer/clip playback/seek/reopen, но ещё не процесс-рестарт всего приложения.
- Экранная проверка скачанного Read Along Chapters при `Active default network:
  none` достигла native фона, но повторный старт обнаружил NPE внутри Media3
  `seekToCurrentPosition` после лишней capability-invalidation. В общем audio
  renderer добавлена только проверка отсутствия изменения MIME; кодек не
  переделывается. Добавлен regression restart-after-ended с production factory.
  Итоговая повторная экранная проверка ещё требуется, сбой не скрывается за
  ранее прошедшими изолированными тестами. Версия нового среза — 0.9.13/code913;
  архивы 0.9.11/0.9.12 не изменяются.
- **Итог среза:** 551 JVM-тест на вариант, оба APK/оба lint проходят; 27 reader
  Node и 14 Python-проверок прошли. Последний локальный runtime regression:
  2 теста дважды, `.local/instrumentation/20261126T102520179598Z/`; отдельно
  прошли online native clip (`20261126T102530579718Z`), Auto (`20261126T102535309031Z`)
  и software decoder (`20261126T102541620094Z`, 4 теста). Проверены обе упаковки
  JNI/лицензии/16 KiB alignment; сертификат подписи не изменился.
- **Сквозная приёмка на retained-эмуляторе, Wi-Fi/data отключены:** скачанный
  Read Along Chapters открыт из «Профиль → Загрузки», при `Active default network:
  none` native MediaSession сохранил PLAYING после Home и за 12 секунд перешёл
  item 2/0 ms → item 3/1782 ms. Подсветка первого фрагмента второй главы видна
  в `offline-narration-highlight.png`. После паузы сохранено 0.849 s точного
  `OEBPS/second.xhtml#one`/`OEBPS/second.mp3`. После `am force-stop`, повторного
  открытия из загрузок без сети и явного Play восстановлено **849 ms** item 2;
  до Play аудиосессии не было. Это проверка force-stop/reopen, не OS low-memory kill.
  JSON-доказательства `.local/contracts/offline-native-narration-{background,
  saved-before-process,process-restore}.json`, screenshot
  `offline-narration-process-restore.png`. Сеть эмулятора затем восстановлена.
- Базовый native offline source и точное восстановление после перезапуска

  слышимость/Bluetooth на физическом устройстве и OS-kill-сценарии. Самопроизвольный

### Новые баги с телефона — 2026-11-26

- [ ] В аудиорежиме прозрачные системные кнопки Home/Back перекрывают нижние
  кнопки приложения. В `PlayerScreen` обнаружен только `statusBarsPadding`, без
  нижнего navigation inset. Нужны безопасные отступы и проверка трёхкнопочной/
  жестовой навигации, включая небольшой экран; физическая приёмка не проведена.
- [ ] При выключенном экране команда «назад на 10 сек» с наушников вызывает
  разрыв/ошибку; с включённым экраном срабатывает со второй-третьей попытки.
  Уточняются точный текст/код ошибки и режим (аудиокнига либо read-along).
  Не считать проблемой Bluetooth без доказательств: проверить seekBack/previous
  MediaSession, HTTP Range/обновление токена, питание/сеть в фоне и переход
  границы треков. В обычном audiobook HTTP DataSource найден захват токена при
  создании экземпляра, без refresh-пути native SMIL; wake mode у ExoPlayer явно
  не включён. Это направления проверки, а не установленная причина бага.

### Основные этапы

**Уточнение приоритетов пользователем (2026-11-24):** автоматическое
перекодирование аудио при невозможности direct play является важнейшей задачей
совместимости наряду с завершением фонового read-along. Не откладывать его за
словарями, статистикой или косметическими правками. Предпочитать оригинал, при
отсутствии подходящего декодера или подтверждённой ошибке неподдерживаемого
формата переключаться на совместимый серверный поток, если такой контракт
доступен. Сетевые ошибки не считать несовместимостью кодека. Сохранять точное
издание/трек и исходную временную позицию; переключение не создаёт новую
READ/LISTEN-активность, дубль очереди или постоянную загрузку. Проверить seek,
переходы между треками, восстановление и применимость к native read-along.
Если сервер не предоставляет транскодирование, явно зафиксировать это ограничение:
изменение производственного сервера не подразумевается разрешённым.

**Требование к синхронизации хайлайтов:** EPUB-выделения используют серверные
аннотации с точным fileId и CFI, текстом, цветом и заметкой. Для комиксов отдельно
проверить сохранение page/image-якоря и координат, ревизии изображения и
совместимость повторного отображения в веб-клиенте. Пока контракт не подтверждён,
не отправлять OCR-геометрию как PDF и не заявлять временное выделение как
синхронизированный хайлайт. Проверить очередь офлайн-операций, повторы без дублей,
изменение/удаление и изоляцию сервера/аккаунта.

**Аудит без изменения сервера:** `docs/AUDIO_COMPATIBILITY.md`, stock-source
`c1dd6b4f1947ff50843a155e12e70f1e7d15f0c7`. Аудио-маршрут отдаёт исходный
файл с Range, playback-transcoding endpoint не обнаружен; FFmpeg здесь относится
к записи метаданных. Для полностью клиентского решения нужны дополнительные
декодеры и, где требуется другой encoded stream, локальный encoder/cache/proxy.
Включён fallback между установленными Media3-декодерами; это **не** готовое
перекодирование. Отдельно подтверждено: сервер отклоняет PDF-аннотацию для CBZ;
OCR-координаты нельзя отправлять под видом PDF. Сервер не менялся.

**Read-along, исторический онлайн-срез 2026-11-24** (локальный путь и force-stop
проверены в срезе 0.9.13 выше): подключается service-owned
native SMIL к существующему `PlaybackService`/ExoPlayer/MediaSession, а не к
второму плееру. Добавлены переключение audiobook/narration, отдельные checkpoints,
команды панели и следование точному SMIL-фрагменту в WebView без web-аудио.
Первый подключаемый путь ограничен онлайн-EPUB (`APP_STREAMING`) и локальным
выходом, без Cast. Для локальных/offline EPUB пока сохраняется прежний foreground
режим. Первый fdroid build/lint/units прошёл; последующие небольшие изменения
управления и RU/EN-подписи пересобираются вместе со вторым вариантом.
Сквозной эмуляторный тест `Read Along Chapters`: после Home MediaSession
остаётся `PLAYING`, clip-relative позиция выросла с 5361 до 8188 ms за 3 секунды.
При возврате открылась вторая глава с подсветкой её точного SMIL-фрагмента.
Доказательства: `.local/contracts/native-service-background.json`,
`native-service-playing.png`, `native-service-return.png` в screenshots.
Пройдены 27 Node-проверок reader, `AutoMediaSessionTest` (1:

Остаются offline native source, восстановление после завершения процесса,

### Streaming clarification requested by the user

Audiobook playback already uses HTTP streaming/Range with Media3 buffering, not an
automatic whole-book offline download. Through 0.9.5 the native EPUB/PDF reader instead
fetches a complete temporary file before opening; calling this true chapter streaming
would be incorrect. The online server Web reader is a separate mode.

The EPUB on-demand mode is implemented in 0.9.6 below. PDF has different seekable-file
requirements and is not streamed merely because EPUB becomes streamed.

## Native online EPUB (0.9.6)

- Settings → Reading → Reader interface → **App · online EPUB** enables on-demand
  chapters/resources through `/epub/{bookId}/info` and `/file/…`, always with the
  exact `fileId`. Existing **App · cached file** remains the default.
- Explicit offline editions take priority in either native mode. PDF/other formats
  still use complete files; the server Web reader remains a distinct mode.
- WebView receives metadata and a scoped resource lease, never JWT. Native HTTP
  authorizes only allowlisted resources of that book/file, blocks redirects and
  cross-account/server reuse, and cancels requests when the lease closes. No whole
  ZIP is written to disk; unsupported streaming fails without a hidden full download.
- Literal-percent asset names account for the pinned server's double-decoding
  behavior. HTTP/Node/JVM checks and emulator rendering cover `art 100%.svg`.
- Embedded read-along works in the foreground with streamed EPUB resources, but
  currently fetches the current audio asset as a whole Blob. This is **not** native
  Media3 range streaming for embedded narration; a large single asset can use
  substantial memory/bandwidth. Ordinary audiobook playback remains separate.
- Stream checkpoints use the captured server content revision; local checkpoints
  use full EPUB SHA-256. Each fingerprint has its own key; 0.9.5 legacy positions
  remain readable. The server's `fileHash` is KOReader partial MD5, not a full-byte
  cryptographic hash. Server API has no atomic archive revision precondition, so an
  archive changed during an open session is not guaranteed byte-consistent.

## Refresh and open-session ownership races (0.9.10)

- Three new refresh regressions initially failed: a delayed old-account response
  could overwrite a new account's token or sign it out, including after a server
  switch. Added generation-bound session leases and synchronized conditional token
  commits/sign-out. Logout/relogin invalidates old leases even for the same user.
- Refresh snapshots request cookies and applies rotated response cookies only
  together with a still-owned token commit. Redirects/retries/authenticators are
  disabled and the rotation body is one-shot. Transient HTTP failures preserve
  offline login; a real 401/403 clears only the still-current session.
- Authorized requests carry an in-process owner tag. A late 401 cannot retry an old
  request with a different account's token; obsolete responses are rejected. An
  explicitly owner-tagged queued request fails before sending after logout.
- Three open-session regressions also initially failed: closing after logout or an
  account switch could relabel the snapshot, and identical file IDs could keep one
  session across accounts. Reading/listening trackers now capture the owner at
  session start, preserve it when queuing, and separate owner generations.
- Session delivery checks row ownership/server data scope and supplies an explicit
  Retrofit owner tag. The tag is not JSON; the server session DTO and stable UUID
  checkpoint/upsert semantics are unchanged. Old already-unowned rows retain their
  documented legacy handling; new owned activity never creates an unowned row.
- Extended isolated HTTP smoke with exact EPUB overlay playlist identities and
  ranged audio bytes across the silent interlude. This validates a contract for the
  upcoming native engine, not background narration itself.
